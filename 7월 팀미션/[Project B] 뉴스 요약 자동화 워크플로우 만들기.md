# 📰 AI 뉴스 요약 자동화 프로젝트

> RSS로 수집한 뉴스 데이터를 자동으로 가져와, Gemini AI로 핵심 내용을 요약한 뒤 Notion 데이터베이스에 저장하는 자동화 시스템입니다.  
> Make(Integromat)를 활용해 **뉴스 수집 → 중복 검사 → AI 요약 → Notion 저장**까지의 전 과정을 하나의 시나리오로 구성했습니다.

---

## 1. 프로젝트 개요

본 프로젝트는 매일 발행되는 방대한 뉴스 중 **관심 주제 기사만 자동으로 선별·요약·아카이빙**하기 위해 설계되었습니다.  
사람이 직접 뉴스를 검색·요약하는 반복 작업을 자동화하여 **시간 절감**과 **정보 관리 효율화**를 목표로 합니다.

---

## 2. 프로젝트 목표

-  관심 키워드 기반 뉴스 자동 수집
-  중복 뉴스 저장 방지
-  AI를 활용한 뉴스 요약 자동 생성
-  Notion을 활용한 뉴스 아카이빙 자동화

---

## 3. 사용 도구

| 도구 | 용도 |
|------|------|
| **Make** | 자동화 시나리오 구성 |
| **Google Gemini API** | 기사 요약 생성 |
| **Notion Database** | 결과 저장 및 관리 |
| **Google News RSS** | 뉴스 원본 데이터 수집 |
| **Gmail** | 오류 발생 시 알림 용도 |

#### 🔄 피드 폴링·실패 시 동작 연계

| 상황 | 시스템 동작 | 영향 및 복구 방안 |
|------|-------------|-------------------|
| **정상 실행** | 최대 5건 수집 후 다음 모듈로 전달 | — |
| **RSS 응답 지연/오류** | Retry 정책(2회·5분)에 따라 재시도 | 일시적 오류는 대부분 재시도로 복구 |
| **스케줄 실행 실패**(누락) | 해당 사이클 기사 수집 누락 | 다음 날 실행 시 최신 기사부터 재수집. `작동 시간` 필드로 누락일 추적 가능 |
| **중복 발생** | 다음 실행 시 URL 중복 검사로 재저장 차단 | 재수집되어도 중복 저장 없이 안전 처리 |


**1) RSS 피드란?**

RSS(Really Simple Syndication)는 뉴스·블로그 등의 최신 콘텐츠를 **표준화된 XML 형식**으로 제공하는 규격입니다.  
사이트를 직접 방문하지 않아도, RSS 주소만 알면 **기계가 읽을 수 있는 구조화된 데이터**를 받아올 수 있습니다.

**2) RSS 피드가 제공하는 데이터 구조**

하나의 기사는 `<item>` 태그 안에 아래와 같은 필드로 구성됩니다.

```xml
<item>
  <title>AI 기술, 산업 전반으로 확산</title>        <!-- 기사 제목 -->
  <link>https://news.example.com/article/123</link> <!-- 원문 링크 -->
  <description>생성형 AI가 다양한 산업에...</description> <!-- 본문 요약 -->
  <pubDate>Mon, 12 Aug 2026 09:00:00 GMT</pubDate>  <!-- 발행일 -->
  <guid>https://news.example.com/article/123</guid>  <!-- 고유 식별자 -->
</item>
```

| RSS 필드 | 제공 데이터 | 본 프로젝트에서의 활용 |
|----------|-------------|------------------------|
| `title` | 기사 제목 | 주제 필터링, Notion 제목 저장 |
| `link` | 원문 링크 | 중복 검사 키, Notion 저장 |
| `description` | 본문 요약 | **Gemini 요약의 입력 데이터** |
| `pubDate` | 발행일 | Notion 발행일 저장 |
| `guid` | 고유 식별자 | (중복 검사 보조 후보) |

**3) Make가 RSS를 가져와 처리하는 원리**

Make의 **RSS 모듈**은 위 XML을 자동으로 **파싱(Parsing)** 하여, 각 필드를 개별 변수로 변환합니다.

```
[RSS 피드(XML)] 
      │  ① HTTP 요청으로 피드 데이터 수신
      ▼
[Make RSS 모듈] 
      │  ② XML을 파싱해 <item>별로 분리 (Bundle 생성)
      │  ③ title·link·description·pubDate를 변수화
      ▼
[다음 모듈에서 {{title}}, {{link}} 등으로 사용]
```

- **① 요청:** 스케줄 트리거가 발동하면 Make가 RSS 주소로 HTTP 요청을 보냅니다.
- **② 파싱:** 응답으로 받은 XML을 기사(`<item>`) 단위로 자동 분해합니다. 기사 1건 = **Bundle 1개**로 처리됩니다.
- **③ 변수화:** 각 필드를 `{{title}}`, `{{link}}`, `{{description}}` 등 후속 모듈에서 바로 쓸 수 있는 변수로 매핑합니다.

>  **핵심:** 요약에 사용하는 `Description`은 RSS가 제공하는 **본문 요약 필드**입니다.  
> 즉, Gemini는 원문 페이지에 직접 접속하는 것이 아니라 **RSS가 제공한 `Description` 텍스트를 입력받아** 요약을 생성합니다.

## 4. 자동화 흐름

전체 시나리오는 다음과 같은 순서로 동작합니다.

1. RSS에서 뉴스 기사 수집
2. **주제 필터링** — 관심 키워드 포함 기사만 선별
3. Notion 데이터베이스에서 동일한 원문 링크가 이미 존재하는지 검색 (중복 검사)
4. 중복이 아니면 Gemini API를 호출하여 기사 요약 생성
5. 제목·요약·원문 링크·발행일을 Notion에 저장
6. 오류 발생 시 Retry 정책에 따라 재시도 및 메일로 알림

## 6. 워크플로우 상세

### 6-1. RSS 뉴스 수집

RSS 모듈을 통해 지정한 피드에서 최신 기사를 자동으로 가져오도록 설정했습니다.  
필요 이상의 뉴스가 수집되는 것을 막기 위해 **최대 5개**의 뉴스를 수집하도록 제한했습니다.


- **RSS 링크:** Google News RSS (`https://news.google.com/rss/search?q=...`)
- **선정 이유:** 네이버 등 일부 포털은 RSS를 지원하지 않아, 가장 보편적으로 넓은 범위를 커버할 수 있는 **Google News RSS**를 선택했습니다.

####  스케줄 트리거 동작 원리

RSS 수집은 **Make의 스케줄 트리거(Schedule)** 를 기반으로 동작합니다.

- **동작 방식:** Make는 내부적으로 스케줄러를 사용해, 정해진 시각에 시나리오를 자동 실행합니다.
- **설정값:** `매일 오후 1시(13:00)` 1회 실행
- **이유:** 점심시간을 활용해 기사를 읽기 위해, **오후 1시**에 실행하여 당일 오전 기사까지 안정적으로 수집하도록 설계했습니다.
- **동작 원리:** 트리거가 발동되면 → RSS 피드에 요청 → 신규 기사 5개를 순차적으로 다음 모듈로 전달합니다.

### 6-2. 주제 필터링

수집된 뉴스 중 **관심 주제와 관련된 기사만** 통과시키기 위한 필터링 단계입니다.

Make의 **Filter** 기능을 사용하여 기사 **제목(Title)** 에 지정한 키워드가 포함된 경우에만 다음 단계로 진행하도록 구성했습니다.

#### 🔑 필터링 키워드 목록

수집된 기사는 필터에 적용되어 제목에 'AI'가 포함된 기사만 다음 모듈로 전송합니다.

- **설계 이유:** 빠르게 변화하는 기술 트렌드를 효율적으로 파악하기 위해, 관련 핵심 키워드를 중심으로 필터 목록을 구성했습니다.

| 분류 | 키워드 |
|------|--------|
| 핵심 | `AI`, `인공지능`, `머신러닝`, `딥러닝` |
| 데이터 | `데이터`, `빅데이터`, `데이터분석` |
| 응용 기술 | `챗봇`, `생성형AI`, `LLM`, `자동화` |

- **필터 조건:** `Title` **Contains** `AI` (OR 규칙으로 키워드 확장 적용)

#### 📐 'AI' 키워드 선정 이유 — 공정성·재현성 관점

주제의 대표 키워드로 **`AI`(및 `인공지능`)** 를 기준으로 삼은 이유는 다음과 같습니다.

| 관점 | 선정 근거 |
|------|-----------|
| **공정성(객관성)** | 특정 기업·제품명(예: `ChatGPT`, `Gemini`)이 아닌 **중립적 상위 개념어**를 기준으로 삼아, 특정 대상에 편향되지 않고 폭넓게 기사를 수집 |
| **재현성(반복 가능성)** | `AI`는 표기가 고정된 명확한 용어로, **누가·언제 실행해도 동일한 필터 결과**를 얻을 수 있음 (표기 변형에 따른 결과 흔들림 없음) |
| **대표성** | 프로젝트 주제(AI·기술 트렌드)를 가장 잘 대표하며, 하위 기술을 모두 포괄하는 최상위 개념 |

### 6-3. 중복 필터링

Notion의 **Search Objects** 모듈을 사용하여, 이미 저장된 기사와 원문링크(URL)가 동일한 경우 저장하지 않도록 구성했습니다.

- **중복 기준:** 원문링크(URL)
- **목적:** 동일 기사 반복 저장 방지
- **필터 조건:** `원문 링크(URL)` **Contains** `{{URL}}`

- **선택 이유:** 본 프로젝트는 저장된 데이터를 **사람이 직접 열람·확인**하는 아카이빙 용도이므로, DB에 그대로 노출되는 **URL을 중복 키로 사용하는 것이 실용적**이라고 판단했습니다.

### 6-4. AI 요약 호출

Gemini API를 활용하여 수집한 뉴스 기사 내용을 자동으로 요약하도록 구성했습니다.

#### 🤖 프롬프트 설계 기준

**사용 프롬프트:**
```
너는 지금부터 내 비서야. 내가 첨부한 링크와 기사 제목을 분석해서 3줄 요약을 해줘.

제목 : {{2.title}}
본문 : {{2.description}}
링크 : {{2.url}}
```

<img width="421" height="860" alt="스크린샷 2026-08-12 111609" src="https://github.com/user-attachments/assets/cd1ea7b6-d882-42e0-8c61-941b401313b5" />


| 설계 요소 | 기준 및 이유 |
|-----------|--------------|
| **입력 데이터** | RSS의 `Description`(본문 요약)을 핵심 입력으로 사용. URL은 원문 확인용으로 함께 전달 |
| **3줄 제한 방식** | 프롬프트에 `"3줄로 요약"` 지시문을 명시하여 출력 길이를 제어 |
| **3줄로 제한한 이유** | 한눈에 파악 가능한 분량으로, 사용자가 **긴 글을 읽지 않고도 핵심을 즉시 이해**할 수 있도록 함 |
| **원문 링크 병기** | 3줄 요약만으로 부족할 경우, 링크를 통해 **전문 확인이 가능**하도록 보완 |

### 6-5. Notion 자동 저장

중복이 아닌 기사에 대해서만 **제목·요약·원문링크·발행일**을 Notion 데이터베이스에 자동 저장하도록 구현했습니다.

- **Connection:** Notion Internal Integration 연결
- **저장 필드:** 제목(Title), 요약(Text), 원문링크(URL), 발행일(Date), 작동 시간(Date)

## 7. 에러 처리 정책

**Retry 에러 핸들러 사용**
- 재시도 횟수: **2회**
- 재시도 간격: **5분**

### ⚙️ Retry 설계 이유

| 항목 | 내용 |
|------|------|
| **Retry 적용 이유** | Gemini API·Notion API 호출 시 발생하는 **일시적 네트워크 오류 / 서버 응답 지연**에 대응하여 자동화의 **안정성**을 확보하기 위함 |
| **재시도 횟수(2회)** | 일시적 오류는 대부분 짧은 시간 내 복구되므로, 과도한 재시도로 인한 지연을 막기 위해 2회로 제한 |
| **재시도 간격(5분)** | 서버 부하·네트워크 문제가 해소될 시간을 고려하여 5분으로 설정 |

스케줄 실행에 실패했을 경우 노션에는 어떤 기록도 저장되지 않으며 표는 빈 상태로 그대로 유지됩니다.
